## 1. 项目概况

**AI 异能大乱斗**——LLM 驱动的异能对战平台。玩家刻印奇术、登台对战，LLM 推演战局、双视角转写、猜词攻防。

- **后端**：FastAPI + async SQLAlchemy 2.0 + Alembic；数据库 PostgreSQL（Docker）/ SQLite（本地测试）；uv 管理依赖
- **前端**：React + Vite（`frontend/`），纯 CSS 样式层
- **部署**：Docker（`Dockerfile` + `docker-compose.yml` + `entrypoint.sh`）
- **开发**：`dev.bat` 一键起（docker compose up → alembic upgrade → uvicorn:8102 → vite:5174）

## 2. 当前架构状态（已核验）

核心在 `app/services/`，服务按业务链路组织，nodes 也按链路分组：

```

battle/   lifecycle.py(对局生命周期)  deduction.py(推演编排)  stream.py(SSE)
          economy.py(见闻/名望)  matchmaking.py(摇签)
guess/    pipeline.py(猜词编排)
llm/      client.py(模型客户端)  reliability.py(可靠性)  profile_crypto.py(密钥)
admin/    test_battle.py(试验场)  prompt_debug.py(提示词调试)
support/  notifications.py(通知)
nodes/ability/ pair_judge.py  describer.py
nodes/battle/  deducer.py  transcriber.py  discusser.py  usage_judge.py
               leak_filter.py  transcribe_validator.py
nodes/guess/   core_judge.py  matcher.py

```

- **猜词链路**（9a5bc6c 重构）：「逐门点评＋主动检定」两环节；原子点评固定为「是 / 否 / 部分是 / 不能确定」；刻印方猜词链路追踪在奇人榜（a35ef83）
- **三相奇术解析**：`ability/understanding.py` 的 `UNDERSTANDING_SYSTEM_PROMPT`（契相/显相/果相），165 个奇术槽位已全量重生成
- **断点续推**：⚠️ 记忆里的独立 `battle_pending` 表已不存在，现改为 battles 表 `status='pending'` 行直接存（`uq_battles_user_a_pending` 唯一约束，story 列缓存分片），`recover_pending_battles` 仍在 main.py/battle/lifecycle.py

## 3. 协作红线（接手人务必遵守）

1. **提示词全部冻结**：`battle/lifecycle.py`、`battle/deduction.py`、`nodes/` 各文件的推演/判定/转写/猜词提示词 + `UNDERSTANDING_SYSTEM_PROMPT` 三相理论，都是用户手调/口述，**禁止修改**（连疑似笔误也不要顺手改）。非提示词代码（占位符、pydantic 字段、结算逻辑）不受限，但要改提示词先问。
2. **git 提交/推送必须先征求许可**：改完代码询问用户，等明确同意再 commit/push。用户有自己管理远程的习惯。
3. **默认不跑全量 pytest 回归**：小改动只跑相关子集；全量回归要用户点名才跑。汇报时写明"跑了哪些子集"，别声称做了全量。
4. **方向性改动前频繁提问**：发现文档/代码冲突时大胆删遗留、简化、重构，但动手前用提问确认，不默默选解释。
