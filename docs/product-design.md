## 1. 产品定位

**一句话定位**：异闻师自写奇术（想写什么就写什么）、装配奇人，向「小天下集」的公开阵容发起挑战；LLM 依据双方奇术与策略一次性推演整场对决并检定胜负，挑战者再凭推演叙述与逐轮点评，猜测守方阵容实际使用的奇术——全部看破即可解锁上帝视角全文。纯机制对抗、无数值强度，靠脑洞与心理博弈驱动。

- **目标用户**：脑洞/脑力型玩家，小圈子（给朋友玩）。
- **核心爽点**：
  1. **奇术保密 + 猜奇术**：推演叙述与点评只给可辨识线索、绝不泄露奇术真名与效果原文——读文、猜奇术本身就是博弈。
  2. **自由创作奇术**：零门槛输入、无限脑洞，机制完全由玩家自己设计。
  3. LLM 铺陈的推演故事与上帝视角揭秘。
- **明确不做**：不逼氪（无充值）、不做实时联机（无 WebSocket）、不做抽卡收集、不做奇术融合、不做数值/强化系统（纯机制对抗）、不做排名与养成数值。

## 2. 核心循环

```
管理员创建并发布卷（名称/背景/规则/胜利条件/判定规则）
        ↓
创作者装配奇人（绑定自己 1-4 门奇术）→ 在卷下发布阵容（奇术快照入库）
        ↓
挑战者对阵容发起挑战（奇术保密，快照隔离）→ 逐对比对双方奇术（Redis 缓存）
        ↓
上帝视角一次性推演（消费比对结论）→ 检定官判定胜利条件是否达成
        ↓
双方视角脱敏转写（SSE 逐字流；挑战者永远看不到守方奇术）
        ↓
挑战者消耗猜测次数道出猜测 → 原子拆分 × 每门未看破奇术并发四态判定（点评累计）
        ↓
主动检定：判定每张卡是否看破、还缺什么
        ↓
全部看破 → 解锁上帝视角全文（衍生数据：看破均值等阵容统计）
```

## 3. 功能设计

### 3.1 用户系统
- 注册 / 登录：JWT 短时 access + refresh 旋转（重用检测即吊销全令牌）；邮箱可绑定/换绑，支持找回密码。
- 注销为软删 + 匿名化；个人数据可导出（JSON 附件）。
- 数据隔离：仅本人可操作自己的奇人、奇术与方案；他人资产一律 404。

### 3.2 奇人与奇术（用户私有可变资产）
- 用户直接拥有 `abilities` 与 `characters`，随时编辑，无发布与版本控制。
- 奇人绑定 1-4 门自有奇术（`position` 有序）；删除奇术自动解除所有绑定。
- `understanding` 为后台异步生成的三相因果槽位 JSON（时序三相因果守恒律），供比对节点附入对比输入；失败静默，比对时退回原文。

### 3.3 小天下集（卷 / 阵容 / 挑战）
- **卷**：仅管理员可创建、编辑、发布、下线；卷名唯一 + ASCII 拼音 slug。
- **阵容**：创作者基于自己的奇人在已发布卷下发布；奇术以快照入库，不随资产后续编辑变化；支持复制与软删。
- **挑战**：对单个阵容发起，三份快照（卷/阵容/挑战者奇人）隔离存储；作者挑战自己阵容为**试炼**，不计公开统计；状态机 `preparing → active → resolving → won/lost/failed`，崩溃遗留由启动自愈兜底。
- **统计**：阵容挑战数、胜率、首次达成平均挑战数（仅首次达成者入均值）。

### 3.4 推演链路（一次性上帝推演）
- **奇术比对**：双方奇术全量跨边配对，逐对结构化判定（三相共鸣理论，必须分出占优）；Redis 缓存按「提示词+模型指纹 × 奇术内容哈希」键控，直接冲突项汇总为权威结论。
- **上帝推演**：一次性推演完整对决（含比对结论槽位），规则优先于策略与奇术发挥；同步推送遮挡进度（真实文本不出站）。
- **胜负检定**：独立检定官依据规则与完整剧情判定胜利条件达成与否，不裁转写。
- **视角转写**：挑战者/守方各自的第一人称脱敏转写并发流式；守方正文永不发给挑战方。

### 3.5 猜词系统（核心）
- **道出猜测**：消耗猜测次数，全文先原子拆分（纯正则，不调模型），每个原子与每门未看破奇术并发四态判定（是/否/部分是/不能确定），结果按完成顺序即时落库并流式推送。
- **点评**：判定文本与内部理由分离；用户可见内容绝不包含奇术真名/效果原文。
- **主动检定**：玩家发起，对每张未看破卡基于「该卡自己的猜测+点评」记录判定——看破或指出缺失方向（缺失只写类别，不泄答案）。
- **全部看破**：解锁上帝视角全文（一次性门控，永久开放）。
- **失败兜底**：单配对/单卡失败不降级整轮；整轮失败退还次数并标记可重试。

### 3.6 无数值
没有任何货币、等级、排名、经验与战斗力数值；对决纯机制对抗。用户可自配 LLM 方案（BYOK）。

## 4. 技术架构

### 4.1 技术栈
- 后端：FastAPI（Python 3.12，uv）+ SQLAlchemy 2.0 async + PostgreSQL（Docker）+ Alembic + Pydantic v2。
- 前端：Vite + React 19 + TypeScript，纯 CSS（古镇纸墨主题），react-router v7。
- LLM：OpenAI 兼容协议统一适配（langchain ChatOpenAI），结构化输出统一 function_calling（DeepSeek 兼容）；默认平台 Key，用户 BYOK 覆盖。

### 4.2 分层规矩（详见仓库根 AGENTS.md）
- `app/services/nodes/<域>/` = 该域 LLM 节点声明；`app/services/<域>/` = 该域服务（编排/缓存/运行时），同名成对。
- 编排属 services（`scenario/flows.py`），路由只做 HTTP 壳；依赖方向 api → services，绝不反向。
- 所有 LLM 调用收口 `llm/reliability.py`（硬超时 + 退避重试 + 并发闸 + llm_traces 追踪）。
- 后台任务 `dispatch()` 双模式：inline 进程内 / arq 独立 worker，共用一张注册表。

### 4.3 数据模型
见 [current-model-api.md](current-model-api.md)（以代码为准的表、字段与接口清单）。要点：用户资产可变、玩法内容（卷/阵容/挑战）快照隔离、`llm_profiles` 密钥 Fernet 加密落库、`llm_traces`/`request_logs` 审计。

### 4.4 前端
23 个路由页面（认证 7、浏览 4、创作 2、挑战 4、设置 1、管理后台 5）+ 复用组件层；古镇纸墨视觉规范与目录速览见 [frontend/README.md](../frontend/README.md) 与 [清理记录-01](清理记录-01-frontend.md)。

## 5. 已定决策

| # | 决策 | 结论 |
|---|---|---|
| 1 | 奇术来源 | ✅ 用户自定义（自由文本），不生成、不抽取 |
| 2 | 推演形态 | ✅ 一次性上帝推演 + 双视角转写（替代旧逐段对战流程） |
| 3 | 猜词判定 | ✅ 原子四态（是/否/部分是/不能确定）+ 玩家主动检定 |
| 4 | BYOK | ✅ 已实现：用户自配 LLM 方案，密钥加密存储，激活即覆盖 |
| 5 | 纯机制对抗 | ✅ 无货币/等级/排名/养成，永不回头 |
| 6 | LLMOps 追踪 | ⏳ 未采用 Langfuse/OTel 自托管方案；现役为 Prometheus /metrics + llm_traces 表，后续迭代再议 |
