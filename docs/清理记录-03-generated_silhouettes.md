# 清理记录 · 第三站：generated_silhouettes/

> 2026-09-18 清理。本站极短：删掉一个**空目录**和一条**死规则**。
> 但"为什么连一个空目录都值得单独立案"本身值得讲清楚——排查过程比结论更有参考价值。

## 一、它是什么

`generated_silhouettes/`（生成的剪影）——名字暗示某次计划中的"AI 生成剪影/立绘"功能。
实际状态：

- 目录**完全为空**（0 个文件）
- 被 `.gitignore` 忽略（第 63 行有一条前导制表符的规则，制表符导致按关键词搜索一直漏掉它）
- 全仓库（前后端代码、配置、文档、Docker、git 全部历史提交）**零引用**

## 二、来历考证

查证手段与结果：

| 手段 | 结果 |
|---|---|
| `git log --all -- generated_silhouettes/` | 从未有提交触碰过它 |
| `git log --all -S "silhouette"`（全历史内容搜索） | 任何提交里都没出现过这个词 |
| 全历史新增文件名搜索 | 没有任何相关文件被加入过 |
| 当前代码引用扫描（py/ts/tsx/css/yml/Dockerfile…） | 零命中 |

结论：它从未属于这个仓库的历史，只是某次（9 月 4 日前后）在磁盘上手动创建的空壳 + 一条配套的忽略规则。既没有功能指向它，也没有代码要写它——**幽灵目录**。

## 三、处置

1. 删除空目录本身（git 本就不追踪空目录，磁盘上删掉即彻底消失）。
2. 删除 `.gitignore` 里那条死规则（规则保护的对象已不存在，留着只会让后来者困惑"这里是不是该有什么"）。

如果将来真要做"生成剪影"功能：建目录、写代码、按需加忽略规则，三件事都是举手之劳，无需为不存在的功能保留占位。

## 四、验证

- `ls generated_silhouettes` → 不存在
- `grep silhouette .gitignore` → 0 命中
- `git check-ignore` → 不再匹配
