## 3. 新增 / 删除奇人 ✅

- **`POST /loadouts`** 已实现：创建新奇人，`name` 必填（空则 400「奇人姓名不能为空」），`style` / `tactic` 可选，`enabled` 默认 True；v3.4 起受**槽位上限**约束（初始 3 槽、每 50 见闻 +1、上限 8，超限 400，见 §8）。

## 5. 「奇人至少一个奇术才能解封」校验 ✅

`routes/loadouts.py::update_loadout` 在 `body.enabled is True` 时校验 `loadout_abilities` 非空，否则 400「奇人还没有奇术，至少装入一个才能解封」。

- 仅对**解封开启**动作强校验；`POST /loadouts` 创建时**不**拦截（可先立空奇人再装入奇术）。
- 前端同样拦截（解封开关 + 无奇术提示）。
- 历史「已解封但空」数据：前端显示「已解封但无奇术，不会被摇签点名」，不改数据。

## 6. 响应瘦身 ⏭️（跳过——前提有误，保留字段）

**原文档前提错误**：声称 `AbilityOut` 的 `detail` / `tactic` / `understanding`「模型已删列，恒返回空串」。经核实：

- `Ability` 模型仍保留这三列，且**是活跃读写**：
  - `understanding`：由 `ensure_ability_understanding` 异步写入，`services/battle.py` 读取生成行迹 `insight_a/b`（`test_battles.py` 断言）。
  - `tactic` / `detail`：由 `routes/abilities.py` 写入（`test_loadouts.py:117-126` 断言）。
- 前端已不再读取这些字段，但**删除会破坏后端功能**（行迹奇术解读、战术写入）。

**决定**：跳过本项，保留字段与 schema，保持模型一致。`AbilityOut` 仍含 `detail` / `tactic` / `understanding`（`model_validate` 填充真实值）。
